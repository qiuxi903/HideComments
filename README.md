# 干掉评论区 · HideComments

> 抖音、快手、哔哩哔哩的评论区，从**入口**到**内容**到**手势**，整条抹掉。
> 按钮不显示、评论打不开、左右滑也滑不进去。

一个 **LSPosed 模块**。装好之后，短视频 App 里那套评论入口就当从来没存在过。

## 效果

装上之后，下面这些位置都会变成「什么都没有」：

| 位置 | 表现 |
|---|---|
| 评论区入口按钮 / 顶栏 Tab | 不显示，也不会闪一下再消失 |
| 评论区面板 | 根本不加载，点开是空的 |
| 左右滑动切到评论页 | 手势被挡，画面纹丝不动 |
| 点击评论按钮、分享链接、深链 | 没反应 |
| 搜索页、简介页、推荐列表 | **完全不受影响** |

最后一行是特意保证的。屏蔽做得太猛是这类模块最常见的翻车方式——搜不到视频、顶栏少一格，那模块就废了。

## ⚠️ 开始之前

这活儿是在 Root 设备上改别人 App 的运行时行为，有两件事得先想清楚：

1. **本模块只改界面，不碰网络。** 服务端收到的请求和你正常刷视频时完全一样，所以「因为用了这个模块被限流/封号」的情况不会发生。
2. **但 Root 环境本身可能被检测。** 本模块**不处理** Root 检测绕过，需要自己配合 Shamiko、Play Protect 之类的隐藏方案。

模块本身不会主动上传任何数据，源码也就几千行，全在这一个仓库里，欢迎自己看。

## 安装

### 1. 先确认你的手机满足条件

| 条件 | 要求 |
|---|---|
| 系统 | Android 8.0 及以上 |
| Root | Magisk / KernelSU / APATCH 任一 |
| 注入框架 | **LSPosed 2.2+** 或 **Vector 2.1+**（需支持 libxposed API 101） |
| Zygisk | 已启用（NeoZygisk / Zygisk Next） |

> 没装框架的话，先去装 [LSPosed](https://github.com/LSPosed/LSPosed)。这一步没得绕。

### 2. 下载并安装

到 **[Releases 页面](https://github.com/qiuxi903/HideComments/releases/latest)** 下载 `HideComments-v1.0.0.apk**，装到手机上。

> 这个 APK 用的是调试签名（debug keystore），能正常安装使用。**以后更新请继续用同一个签名**，
> 换了签名就得先卸载再装，模块的设置和授权都会丢。

### 3. 在框架里启用

1. 打开 **LSPosed / Vector 管理器** → 「模块」→ 勾选 **干掉评论区**
2. 点进模块详情 →「作用域」→ 勾选你要屏蔽的 App
   （默认 9 个包名都预置好了，一般不用改）
3. **强制停止**目标 App（不是划掉，是从后台彻底清掉），再重新打开

第 3 步的「强制停止」别省。模块是在 App 进程启动时注入的，进程还活着的话改了设置也不会生效。

### 4. 确认装好了

打开「干掉评论区」，顶部应该显示这样一行：

```
LSPosed 2.2.1 · API 101 · 已授权 4/4
```

看到它就说明模块和框架已经连上了、设置能传进目标 App。

如果显示「未连接到 Xposed 框架」，基本是第 3 步的作用域没勾，回到那里检查。

## 怎么用

### 主页

| 开关 | 作用 |
|---|---|
| 启用屏蔽 | 总开关，关掉就全部恢复 |
| 抖音 / 快手 / 哔哩哔哩 / 国际版 | 按 App 单独开关，互不影响 |
| 本次放行 | 临时放行某个 App，「我就看一眼评论区」用这个；想恢复屏蔽再点一下变回去 |

### 更多设置

| 开关 | 作用 |
|---|---|
| 隐藏评论区入口按钮 | 顶栏和页面上的评论入口不显示 |
| 隐藏评论区面板 | 评论区内容不显示 |
| 拦截跳转到评论页 | 点评论按钮、点分享链接都进不去 |
| 识别强度 | 见下 |

**识别强度**决定「认得多准」，也决定「误伤概率」：

| 档位 | 怎么认 | 什么时候用 |
|---|---|---|
| 保守 | 只认控件 ID 名和类名里带 `comment` / `reply` / `cmt` 的 | 某个 App 出现了奇怪的界面问题 |
| **标准**（默认） | 上面 + 认「评论」「回复」这类明确文案 | 日常就用这个 |
| 激进 | 上面 + 按控件的尺寸位置猜 | 某个 App 的评论区没被挡住时才开 |

**改设置不用重启目标 App**，2 秒内自动生效。

## 常见问题

**Q：评论区还是冒出来了。**

按顺序试：① 强制停止目标 App 重开；② 识别强度调成「标准」；③ 换「激进」试一次。都不行就是那个 App 改版了，提 issue 附日志。

**Q：打开 App 的时候评论入口闪一下才消失。**

这是时序问题：App 是先把控件插进界面、之后才设文字，早期版本只能等扫描盖住。当前版本已经在 `setText` 这一层直接拦了，正常不会闪。如果还闪，多半是该 App 换了实现，提 issue。

**Q：搜索结果、视频列表会不会被误伤？**

不会。模块里有一条专门的规则：列表里的**每一条内容**（搜索结果里的一个视频、评论列表里的一条评论）都绝不会被当成评论区藏掉。发现搜索页被误伤的话请提 issue。

**Q：会不会影响我正常刷视频、点赞、关注？**

不会。模块只动跟评论相关的控件，播放、点赞、关注、分享、设置这些一概不碰。

**Q：会不会被官方检测到？**

模块不改网络请求，服务端看不出异常。但**你的 Root 环境**可能被检测——这和用不用本模块无关，需要自己配合隐藏方案。

**Q：某个 App 完全没反应。**

三步排查：① 框架里这个 App 的作用域勾了吗；② 强制停止重开了吗；③ 打开模块主页，看底部那行「已授权 N/4」，N 里有没有它。

**Q：想临时看一眼评论区。**

主页每个 App 右边有「本次放行」，点一下这个 App 就恢复正常，退出后再点「恢复屏蔽」就回来。

**Q：怎么反馈问题？**

提 issue，并附上日志。日志不用 root 就能拿：手机文件管理器直接打开

```
/sdcard/Android/data/<包名>/files/hidecomments/module.log
```

路径速查在「更多设置 → 日志与 View 树 → 显示路径」，可以长按复制。

## 它是怎么做到的

<details>
<summary>展开看看原理</summary>

评论区不是一个控件，而是一条链：入口按钮 → 面板容器 → 数据层，外面还挂着一套翻页手势和一堆跳转深链。堵住任何一层，都能从别的方向绕回来。所以模块同时布了五道防线：

| 层 | 手段 | 拦的是 |
|---|---|---|
| 文字层 | hook `TextView.setText` | 「评论」两个字根本不进控件，闪现在物理上不可能发生 |
| 容器层 | 往上找到 Tab 项和面板容器 | 顶栏不会留一个空位，评论数也不会露出来 |
| 手势层 | 拦触摸分发 | 翻页器不接管手势，RecyclerView 一个像素都不动 |
| 跳转层 | 拦点击和 `startActivity` | 点评论按钮、深链进评论页，都没反应 |
| 兜底层 | 周期扫描 + 每帧重申 + 插即隐 | App 把控件重新显示出来、或者动态插入新控件，都盖得住 |

还有两个地方特别难，值得一提：

- **「评论页是第几页」只能从标签栏推。** 抖音的主界面本身就是个 ViewPager2，评论面板挂在首页那一页里——如果按「面板在哪一页」去推断，会把第 0 页当成评论页，**整个主界面切换都会被卡死**。所以只认「顶栏里写着『评论』的那个 Tab 的下标」。
- **hook 点按签名找，不按名字找。** B 站把 androidx 也一起混淆了，ViewPager 的 73 个方法里页面切换那几条被改名成 `A (IZ)V`、`B (IIZZ)V` 这种，`setCurrentItemInternal` 一个都找不到。只能改成「找这个类自己声明的、第一个参数是 int、返回 void 的方法」，再在 hook 里用页码范围二次确认。

</details>

## 自行构建

<details>
<summary>展开构建步骤</summary>

需要 **JDK 17+** 和 **Android SDK 36**。

```bash
# 调试包，免签名，直接能装
./gradlew :app:assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

在 `local.properties` 里配 SDK 路径：

```properties
sdk.dir=G\:\\DevTools\\Android\\Sdk
```

要出正式签名的包，先复制一份 `keystore.properties.example` 改成 `keystore.properties`，
填上自己的签名信息，然后：

```bash
./gradlew :app:assembleRelease
```

> **项目路径含中文**时有两处必需配置，已经写进 `gradle.properties`：
> `android.overridePathCheck=true` 让 AGP 接受非 ASCII 路径，
> `kotlin.compiler.execution.strategy=in-process` 解决 Kotlin 守护进程把中文路径转义后 javac 找不到文件的问题。

| 组件 | 版本 |
|---|---|
| JDK | 17+ |
| Kotlin | 2.4.21 |
| AGP | 8.7.3 |
| Gradle | 8.14.4（wrapper 已含） |
| compileSdk | 36 |
| minSdk | 26 / targetSdk 34 |

</details>

## 已知限制

| 限制 | 说明 |
|---|---|
| Compose 界面 | 抖音部分新界面用 Compose 渲染，传统的 View 树扫描覆盖不到，只能靠 dex 索引在 Fragment 层兜底，覆盖率不确定 |
| App 改版 | App 改版后内部的控件名字可能变，识别会失效。**失效只是少一层保险，不会反过来误伤** |
| Root 检测 | 不处理绕过检测，需要 Shamiko 等方案配合 |
| App 之外 | 只在 App 进程内生效；通知栏、系统分享面板里的评论摘要管不了 |
| B 站国内版 | 实机验证的是国际版，国内版结构大概率相同但没验证过 |
