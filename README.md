# 干掉评论区 · HideComments

> 一个 **LSPosed 模块**，把短视频 / 长视频 App 的评论区从根上抹掉 ——
> 入口按钮不显示，评论区打不开，**左右滑动也滑不进去**。

不是「藏个按钮」那么简单。评论区是一条链：入口按钮 → 面板容器 → 数据层，
外加一套翻页手势和一堆跳转深链。堵住任何一层，都会被从别的方向绕回来。
所以这个模块布了**五道防线**，把每一个入口都封死。

```
┌─────────────────────────────────────────────────┐
│  ① 文字层   TextView.setText     「评论」设不进去 │
│  ② 容器层   Tab / 面板整体 GONE                  │
│  ③ 手势层   onInterceptTouchEvent 手指滑不进去   │
│  ④ 跳转层   performClick / startActivity         │
│  ⑤ 兜底层   View 树扫描 + 每帧重申               │
└─────────────────────────────────────────────────┘
```

---

## 效果

| 位置 | 结果 |
|---|---|
| 评论入口按钮 / Tab | 不显示，不闪 |
| 评论区面板 | 不加载，不显示 |
| 左右滑动切到评论页 | 手势被挡，画面纹丝不动 |
| 点击评论按钮 / 深链 | 无响应 |
| 搜索页、简介页、推荐列表 | **完整保留，不误伤** |

最后一行是重点。屏蔽做得太激进是这类模块最常见的翻车方式 ——
一个视频搜不到、Tab 栏少一格，模块就废了。

## 环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Android 8.0+（API 26） |
| 手机 | 已 root（Magisk / KernelSU / APATCH） |
| 注入框架 | 支持 **libxposed API 101+**（LSPosed 2.2.1 / Vector 2.1+ 实测可用） |
| Zygisk | 需启用（NeoZygisk / Zygisk Next） |

> **为什么是 API 101 而不是 102**：
> `libxposed:api:102.0.0` 的 AAR 元数据要求 `compileSdk 37`，而 android-37 目前只在 Google 的 canary 通道里，
> 普通 SDK Manager 装不了。101 只要求 36（稳定版），在 LSPosed 2.2.1 上行为一致，
> 代价只是失去 `setId` / `detach` / 热重载 —— 对本项目没有实质影响。

## 快速开始

### 1. 构建

```bash
# 调试包（免签名，直接能装）
./gradlew :app:assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

需要 JDK 17+ 和 Android SDK 36。`local.properties` 里配 `sdk.dir`：

```properties
sdk.dir=G\:\\DevTools\\Android\\Sdk
```

> ⚠️ **项目路径含中文**时有两处必需配置，已经写进 `gradle.properties`：
> `android.overridePathCheck=true`（让 AGP 接受非 ASCII 路径）和
> `kotlin.compiler.execution.strategy=in-process`（Kotlin 编译守护进程把中文路径转义后 javac 找不到文件）。

发布包需要根目录放一个 `keystore.properties`（格式见 `keystore.properties.example`）：

```bash
./gradlew :app:assembleRelease
```

### 2. 安装

1. 安装 APK
2. 打开 **LSPosed / Vector 管理器** → 模块 → 勾选「干掉评论区」
3. **作用域**里勾选目标 App（已预置全部 9 个包名，一般不用改）
4. **强制停止**目标 App，重新打开

### 3. 确认生效

打开「干掉评论区」，顶部状态条应该显示：

```
LSPosed 2.2.1 · API 101 · 已授权 4/4
```

看到这一行，说明设置 App 已经通过框架连上了、配置能传进宿主进程。
如果显示「未连接到 Xposed 框架」，多半是第 3 步的作用域没勾。

## 设置项

主页只留最常用的：**总开关 + 四个 App 开关**。其余在「更多设置」里。

| 页面 | 内容 |
|---|---|
| 主页 | 总开关、App 开关、本次放行、一行框架状态 |
| 更多设置 | 屏蔽内容、识别强度、高级选项、框架状态、日志路径 |

| 开关 | 作用 |
|---|---|
| 总开关 | 全局启用 / 停用 |
| App 开关 | 按产品单独开关 |
| 本次放行 | 临时恢复当前 App 的屏蔽，手动点回「恢复屏蔽」才结束 |
| 隐藏入口按钮 | 不显示评论区入口 |
| 隐藏评论区面板 | 不显示评论区内容 |
| 拦截跳转 | 不响应跳评论页的点击 / 深链 |
| 识别强度 | 保守 / 标准 / 激进 |

**识别强度**决定误伤概率：

| 档位 | 判定依据 | 误伤风险 |
|---|---|---|
| 保守 | 只认资源 ID 名和类名里的 `comment` / `reply` / `cmt` | 最低 |
| 标准（默认） | 上面 + 文字精确匹配（「评论」「回复」「Comments」） | 低 |
| 激进 | 上面 + 按尺寸位置猜测容器 | 最高，可能误伤大列表 |

> 改了设置**不用重启目标 App**，2 秒内自动生效。

界面按 **MIUI / HyperOS** 视觉规范做的：主色 `#3482FF`、纯白卡片零描边、18dp 圆角、组内细线左缩进对齐文字。

## 工作原理

工程分三个 Gradle 模块，职责严格分层：

```
app/    设置界面 + Xposed 打包入口
core/   纯数据层：配置模型、目标 App 映射
hook/   注入层：通用引擎 + 各 App 的专属策略
```

两个关键机制值得单独说：

**页码只能从标签栏推。**
翻页守卫需要知道「第几页是评论页」。抖音的主界面（首页/朋友/消息/我的）本身就是 ViewPager2，
评论面板挂在首页那一页里 —— 按「面板在哪一页」推断会把第 0 页当成评论页，
**整个主界面切换会被拦死**。所以只认「标签栏里明确写着『评论』的那个 Tab 的下标」。

**按签名找 hook 点，不按名字。**
B站把 androidx 一起混淆了：ViewPager 的 73 个方法里，页面切换那几条被改名成
`A (IZ)V` / `B (IIZZ)V` / `j (I)V`，`setCurrentItemInternal` 这种名字一个都不存在。
所以改成「只认这个类自己声明的、第一个参数是 int、返回 void 的方法」，再在 hook 体里用页码范围二次确认。

完整架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 排查

日志和 View 树都落在**目标 App 的外部目录**，手机文件管理器直接打开，不需要 root：

```
/sdcard/Android/data/<包名>/files/hidecomments/
├── module.log          运行日志
└── viewtree-*.txt      View 树（需在设置里开启「导出 View 树」）
```

关键日志：

| 日志 | 含义 |
|---|---|
| `==== HideComments 配置已生效 ====` | 设置成功传进宿主进程 |
| `拦下评论文字「评论」` | 文字层生效 |
| `隐藏评论 Tab：...` | 容器层生效 |
| `学到：评论 Tab 在 ... 的第 1 页` | 页码学习成功 |
| `不让手势滑向评论页` | 手势层生效 |
| `hidden[panel] ...` | 实际藏掉了哪个控件 |

**View 树导出**是最快的定位手段 —— App 混淆之后，硬编码的类名锚点基本都失效了，
但导出来的真实控件名不会骗人。每行格式：

```
类名  #资源ID名  [宽x高]  文字  <== MATCH
```

带 `MATCH` 的就是模块认出来的地方。

更完整的排查流程见 [ARCHITECTURE.md](ARCHITECTURE.md#六使用方法)。

## 已知限制

| 限制 | 说明 |
|---|---|
| Compose 界面 | 抖音部分新界面用 Compose，View 树遍历无效，只能靠 dex 索引在 Fragment 层兜，覆盖率不确定 |
| 类名漂移 | App 改版后硬编码锚点可能失效 —— 但失效只是少一层保险，不会误伤 |
| Root 检测 | 不处理绕过检测，需 Shamiko 等方案配合 |
| App 外 | 只覆盖 App 进程内；通知栏、系统分享面板里的评论摘要不在范围 |
| 国内版未实测 | 实机验证的是 B站**国际版**，国内版结构大概率相同但未验证 |
| 快手正式版未实测 | 实机验证的是快手**极速版** |
